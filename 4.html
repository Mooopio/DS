3. The learning setup (very testable)
  • Target function f: the true relation (e.g. x predicts y). Unknown.
  • Training examples: input points with their corresponding outputs. We usually do not have all the data.
  • Hypothesis set H: all candidate functions (here every possible line). Written with script H (the script style has a fixed meaning; do not write it freely).
  • Learning algorithm (here PLA): picks one hypothesis h from H using the data.
  • Final hypothesis g: the best approximation to f that we found.
  • Model: wᵀx + bias (a one-dimensional x reflects directly in y, plus the bias).

Pick a different h (a different line) and the answer for a new, unseen point may change (positive vs negative). That is why we study how reliable learning is.

4. Population vs sample; feasibility of learning

Population = all data (may be unknown, or known but impractical to enumerate, e.g. a statistics agency cannot reach everyone). Sample = the part we actually have. We want to learn about the population from the sample.

Choosing a sample: guided (chosen deliberately, e.g. interview across married/single, working/not, to represent the population) vs completely random. A single sample can be biased (e.g. only reds or one province).

Feasibility study analogy: is learning worthwhile? Yes, as long as we apply it carefully. Beware over-simplification that ruins the idea. Trick: don’t stop at one sample; take many samples.

5. Probability basics
  • Independent events: knowing one tells nothing about the other (drawing balls from a bag blindly, with no preference).
  • Dependent events: linked (two friends who always enter the lecture together).
  • Binary event: P(red) = μ, so P(not red) = 1 − μ. Probabilities of all outcomes sum to 1 (e.g. 70% + 30%).
  • Joint probability of independent events = multiply, so it is smaller (10% × 10% = 1%, not 20%).
  • Possible (can happen) is not probable (reasonable chance). A near-zero chance is possible but not probable.
6. The coin experiment (the key calculation)

A fair coin: P(heads) = ½. P(10 heads in a row for one person) = (½)¹⁰ = 1/1024. P(not all heads) = 1023/1024.

With 1000 independent people, each flipping 10 times: P(nobody gets 10 heads) = (1023/1024)¹⁰⁰⁰ ≈ 0.376. So P(at least one gets 10 heads) = 1 − 0.376 ≈ 0.62 (the lecturer rounded to “≈63%”, which is 1 − 1/e). A rare event for one trial becomes likely over many trials. “At least one” is solved with the complement: 1 − P(none).

Lesson for learning: a rare fluke in a single sample is likely when we try many hypotheses/samples, so be careful.

7. Exponential growth and Euler’s number e

Linear: constant change. Exponential y = bˣ: the change itself changes (slope is not constant); a tiny change in the exponent gives a large change in y. Base b > 1 → grows; base between 0 and 1 → decays.

e ≈ 2.718 (Euler’s number) is the special base: the tangent line at any point of eˣ has a slope equal to the function’s value there. Seen in galaxies’ growth, chemical equations, and any process that repeats many times.

Link: lim (1 + 1/n)ⁿ = e as n → ∞, and lim (1 − 1/n)ⁿ = 1/e ≈ 0.37. So with n tries each of chance 1/n, P(at least one success) → 1 − 1/e ≈ 0.63. That is why the coin result is ≈ 63%.

Common mistakes & traps

Adding probabilities of independent events instead of multiplying (10% and 10% is 1%, not 20%).
Confusing possible with probable.
Mixing up f (true, unknown) with g (our final approximation) or h (any candidate).
Calling clustering supervised (it has no labels).
Thinking exponential slope is constant, or that e is just a random number.
