Lecture 3: Hoeffding & Generalization

1. Where we are: the problem

We want a final hypothesis g that approximates the unknown target f (picked from a hypothesis set H using training examples). The population can never be fully known (impossible, or too large to count, like a census), so we only have a sample. Learning is therefore approximate, never exact.

Notation: μ = the true fraction in the population (e.g. of red balls, or of mistakes on all data); ν (written as “the Greek letter that looks like v”; the lecturer notes it is the same idea as the sample fraction) = the same fraction measured in the sample. We can compute ν, but never μ.

2. The “bad event”

A bad event = the sample misleads us: our prediction on a new point is wrong because ν is far from μ. Formally: |ν − μ| > ε (ε = a tolerance threshold we choose). We want the probability of this bad event to be as small as possible (we minimize the chance of something bad; we do not maximize it).

Proxy idea: we cannot see the population, so we use more sample data as a stand-in; more data = closer to the population = better hypothesis g.

3. Hoeffding inequality (the main result)

P( |ν − μ| > ε ) ≤ 2 e−2ε²N

  • N = number of examples in the sample. Bigger N → exponent more negative → bound shrinks exponentially (this is why Euler’s e appeared in the last lecture).
  • ε = tolerance. Smaller ε (stricter) → weaker bound; larger ε → stronger bound.
  • The bound does not depend on μ (the unknown population value) and holds for any distribution.
  • The factor 2 (two-sided: ν could be above or below μ). The right side may even exceed 1 for small N, which is still true, just useless.
  • It is an inequality (≤), not equality, so it gives an approximation only.

PAC idea (Probably Approximately Correct): Probably = the bad event is now a measurable probability (not just “possible”); Approximately = we only say the difference is below ε, never exactly equal. So Hoeffding makes learning probable and approximate, and it relies on statistics because we sample.

Warning: you can’t shortcut by making N huge forever, since you can’t observe the whole population in practice, and memorizing is a risk (section 5).

4. Measuring hypothesis quality: errors
  • Classification: error = number/fraction of misclassified points.
  • Regression: error = vertical (y) differences between line and points, summed.
  • In-sample error Ein (on training data, plays the role of ν) vs out-of-sample error Eout (on all data, plays the role of μ). Hoeffding says E_in ≈ E_out with high probability.
  • Two hypotheses can look very different yet be equal for us if they make the same errors. We prefer the hypothesis with the smaller error.
5. Overfitting and testing
  • More data reduces the gap, but you must not simply memorize patterns: if an unseen point arrives, a memorizer answers wrong (analogy: reading two or three books and believing you know everything; or memorizing the slides without understanding).
  • Testing: testing on the training data tests only memory (“1+1=2, then asked 1+1”). So hide some data and test on it. Example: 1000 points, train on 700, test on the rest; repeat with different random subsets (not always the same ones).
  • Learning has two sides: collecting more points reduces misclassification risk, but you must also actually understand the topic so the model generalizes.
6. Many hypotheses: the factor M

Hoeffding applies to one fixed hypothesis (verification). In learning we try M hypotheses (lines h₁…hM) and pick g, so the bad event can occur for any of them. Summing over hypotheses (union): P(bad) ≤ 2M e−2ε²N.

Two knobs: N (data points) and M (number of hypotheses). Both matter and they complement each other: you need enough data relative to the number of hypotheses.

Also: we never know the true f, so the guarantees are approximate, which is why different observers might phrase the same question differently but the math is the same.

Memory triggers

“N up, risk down.” N sits in the exponent with a minus sign.
“M multiplies the worry”: more hypotheses, more chances for a fluke.
“PAC” = Probably + Approximately Correct.

Common mistakes & traps

Thinking Hoeffding gives an exact probability: it is an upper bound.
Thinking the bound depends on μ; it does not.
Mixing ν (sample) and μ (population), or E_in with E_out.
Testing on training data (that only tests memory).
Believing “just keep increasing N” solves everything: memorizing patterns still fails on unseen data.
Forgetting the factor M when choosing among many hypotheses.
