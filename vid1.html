1 · What is the course & what is learning?

The course runs from abstract theory to extreme practice (“rules of thumb”). Storyline: What is learning? → Can we learn? → How to do it? → How to do it well? → Take-home lessons. Colours: red = theory early, blue = practical late. Lecture 3 (linear models) is deliberately out of sequence: it gives you tools to experiment with early.

Premise of learning: use a set of observations (data) to uncover an underlying process (in our case the target function).

Statistics does the same (process = probability distribution, observations = samples). Broad premise ⇒ rediscovered in many fields. A “type” of learning exists when its assumptions need their own maths and algorithms.

2 · The 3 ingredients of a learning problem (Netflix)

Netflix paid $1 million to the first team improving its recommender by just 10%: better recommendations → more rentals → far more profit. Same logic in financial forecasting: tiny gains = lots of money.

ML is applicable when:
1️⃣ A pattern exists (no pattern = nothing to learn).
2️⃣ We cannot pin it down mathematically (else just write the formula/code).
3️⃣ We have data (first question to any client: “What data do you have?”).

Movie example: ratings relate to a viewer’s other ratings and other viewers’ ratings (pattern), but you can’t write a “17th-order polynomial” for it.

3 · Movie-rating solution (latent factors)

Hand-made way (not ML): describe viewer as a vector of tastes (likes comedy? action? blockbuster? lead actor?) and movie as a vector of contents. Match coordinates and add contributions → predicted rating. Problem: you must watch every movie and interview every viewer.

Learning way: start with random viewer and movie vectors (≈300 factors). Take an actual rating, nudge both vectors so their inner product moves toward that rating. Repeat over ~100 million ratings, cycling many times. Factors become meaningful; for an unseen (viewer, movie) pair, the inner product predicts the rating. This was one of the winning solutions.

💡 Analogy: tuning thousands of radio knobs a tiny bit each time you hear a wrong note, until the song comes out right.

Reading it: you don’t control f or the data (the client dictates them). You choose H and A (your solution tools) and hand back g.

Learning model = hypothesis set + learning algorithm. Perceptron+PLA · Neural network+backpropagation · SVM (RBF)+quadratic programming.
5 · Why include a hypothesis set H at all?

No downside: in practice you already say “I’ll use linear / NN / SVM” (that is picking H). If you refuse to restrict, H = all possible functions, so no generality is lost.
Upside: H plays a pivotal role in the theory — it decides can we learn and how. The H-size/complexity vs data question is answered in later lectures.

6 · The Perceptron (the simple model)

Weight each attribute, add linearly = credit score, compare with a threshold. Salary → big positive weight; outstanding debt → negative weight.

h(x) = sign( Σᵢ₌₁ᵈ wᵢxᵢ − threshold ) → +1 approve if positive, −1 deny if negative.
Trick: set w₀ = −threshold and add artificial x₀ = +1 ⇒ h(x) = sign(Σᵢ₌₀ᵈ wᵢxᵢ) = sign(wᵀx) (inner product).

Parameters that define one hypothesis: w₁…w_d and the threshold (w₀). Geometrically (if data are linearly separable) h is a line (plane in higher d); changing weights moves the line. The algorithm starts with random weights = random line and moves it until good customers and bad ones are on opposite sides.

If wᵀx = 0 exactly: technical detail. Lecturer’s convention: sign(0)=0, so it counts as an error either way.

7 · Perceptron Learning Algorithm (PLA)

Misclassified point ⇔ sign(wᵀxₙ) ≠ yₙ. Fix it:

w ← w + yₙ·xₙ  (iterate t = 1,2,3,…; pick any misclassified point each time)

Intuition: inner product positive ⇔ w and x “agree”. If y=+1 and they disagree, add x to pull w toward x; if y=−1 and they wrongly agree, subtract x. This is only motivation — it doesn’t prove it works.

Catch: fixing one point may break others that were right. Still, if the data are linearly separable, PLA is guaranteed to converge to a solution classifying all points correctly (needs a proof; “not that hard”). It can take very long (badly with dimension; pathological cases take forever).

Not separable? PLA never stops (always some misclassified point) and can jump from very good to terrible. Use the pocket algorithm (same rule, small modification) or a nonlinear transform (next lectures). In practice assume data is not separable.

Key warning: matching historical records ≠ good on future customers. That is the whole point of the theory.

  • Supervised: “as if a supervisor helps you”.
  • Unsupervised: number of clusters can be ambiguous; one labelled coin per cluster afterwards is enough (instead of many examples).
  • Reinforcement: backgammon target = best move given board state; generating those requires being an expert already (vicious cycle), so let the computer try any move, win/lose, propagate credit. Done ~100 billion times, days of CPU.
9 · The learning puzzle (why learning seems impossible)

3×3 black/white patterns: 3 examples labelled −1, 3 labelled +1, then a test point. Audience mostly said +1, a few −1. Both answers are valid: e.g. rule “top-left square” gives one answer, rule “pattern is symmetric” gives the other; infinite consistent functions exist.

f is truly unknown (could be anything), and a finite sample says nothing guaranteed outside it. Memorising ≠ learning. Resolution (next lecture): learning is feasible without changing the premise that f is unknown.
10 · Q&A highlights (examinable ideas)
  • Sampling bias: bank only sees outcomes of accepted applicants; boundary still works decently since rejected ones are usually deeper in the “bad” region.
  • How much data? Theory answers it later; in practice you don’t control N (100 million vs <100 points).
  • Bigger H fits better but memorises (e.g. 7,000-order polynomial on 50 points); complexity of H dictates data needed. Validation (later) gives feedback.
  • Don’t look at your data to pick the model (tailoring to one dataset: “data snooping”). Ask the client about the process instead.
  • ML vs statistics: ML = fewest assumptions, widest territory; statistics = more assumptions, rigorous proofs.
  • Optimization is a tool, not the goal (e.g. QP for SVM); local vs global minima come with neural nets.
  • H can be finite or continuous/infinite; learning still possible under a theory condition.
  • Bottleneck of ML is generalization, not computation time. Perceptron: bad computationally, good for generalization (simple model).
  • Output can be real-valued (linear regression, lecture 3). Learning algorithm usually minimises an error function; H matters more than A for generalization. Error measures: next lecture week.
  • Perceptron ↔ neuron: neuron fires (+1) if combined stimuli exceed a threshold.
  • Unlearnable: a pseudo-random target — no pattern. Model selection / Bayesian view come late (“last but not least”).

Smart Summary

  • Learning = data → underlying process. Need: pattern + no formula + data.
  • Notation: input x, output y, target f (unknown), data (xₙ,yₙ) N pts, hypothesis set H, algorithm A, final g ≈ f.
    • Model = H + A. You choose H, A; client gives f, data.
    • H: no loss of generality; crucial for theory.
  • Perceptron: h(x)=sign(wᵀx), w₀=−threshold, x₀=1. Line/plane. PLA: w←w+yx on a misclassified point.
    • Converges iff-ish: guaranteed when linearly separable; else pocket / transforms.
  • Types: supervised (labels) · unsupervised (no labels, clusters) · reinforcement (graded output).
  • Puzzle: many functions fit the sample ⇒ naive learning impossible ⇒ theory needed.
  • Real concern: performance on new data (generalization), not fitting history.
  • Movie ML: random factors, nudge, 100M ratings, inner product. Netflix $1M for 10%.

⚠ Common mistakes & traps

  • “PLA converges on any data” ✗ — only if linearly separable.
  • “Matching history means good future” ✗.
  • Forgetting x₀=1 is artificial, and w₀=−threshold.
  • Saying H is optional/harmful ✗.
  • Thinking f is eventually known ✗ — always unknown.
  • Believing computation is the main ML bottleneck ✗ — generalization is.
  • “Perceptron generalizes badly” ✗ — computationally slow, generalization good (simple).
  • Choosing the model by inspecting the data ✗.
