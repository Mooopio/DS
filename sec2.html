🧠 Week 2: PLA, Pocket & MNIST

Deep Explanation

1. What is a perceptron?

A perceptron is the simplest artificial neuron: it takes numbers in, weighs how much each one matters, adds them up, and makes a yes/no decision.

  • A single perceptron can only implement linearly separable functions: classes you can split with one straight line (2D) or one flat hyperplane (higher dimensions).
  • It takes real-valued inputs, attaches a set of weights to them, along with a bias.
  • Multiply each input by its weight and add: the weighted sum.
Σ wᵢ·xᵢ + b = x₁w₁ + x₂w₂ + … + xₙwₙ + b
Analogy: deciding whether to go out. Inputs = weather, free time, friends going. Weights = how much you care about each. Bias = your baseline mood: how easily you say "yes" even with weak inputs. If the total passes your threshold → go (1), otherwise stay (0).

Why bias? The slides say the bias is an essential term added to the weighted sum to improve model performance. Geometrically it shifts the decision line away from the origin; without it the line must pass through (0,0).

2. The x₀ = 1 trick (the "more accepted convention")

Instead of carrying b separately, add a fake input x₀ = 1 with weight w₀ = −θ (θ = threshold). The bias becomes just another weight.

y = 1 if Σ(i=0..n) wᵢ·xᵢ ≥ 0 y = 0 if Σ(i=0..n) wᵢ·xᵢ < 0 where x₀ = 1 and w₀ = −θ

In the diagram, a single "sample" has x₀=1 (the bias input, in green), x₁, x₂… Each is multiplied by w₀, w₁, w₂…, summed over the features, passed through an activation, giving a binary value. Slide note: it is x_1 not x-1: subscripts, not subtraction.

Why it matters: now the sum is a single dot product w·x, and the "threshold" is always 0. This makes the update rule clean.
3. The three-step loop: activate → compare → adjust
  1. Apply an activation function (typically a step or sign function) to the weighted sum → predicted output ŷ.
  2. Compare the predicted output with the desired output (class label y) for that input example → error.
  3. Adjust the weights and bias based on the error between predicted and desired output.

Diagram: inputs x₁…xₘ with weights w₁…wₘ and bias b → net input function (Σ) → activation function (φ) → predicted class label ŷ (0 or 1). The top part (Prediction) is forward; the Error → "weights & bias update" part is Update.

Which activation? Depends on your labels

LabelsActivation
(0, 1)Heaviside step function
(−1, 1)Sign function

Binary labels generally appear as −1,1 or 0,1.

4. Vectorized form: the dot product

A prediction is step(Σⱼ wⱼxⱼ), and its vectorized equivalent is step(w · x): the dot product of weights vector w and features vector x.

w = [w₀, w₁, w₂, …, wₙ] x = [1, x₁, x₂, …, xₙ] w · x = wᵀx = Σ(i=0..n) wᵢ·xᵢ

Note x starts with 1 (the bias input) and w starts with w₀ (the bias weight).

5. PLA: the actual algorithm

Goal: find the w vector that perfectly classifies positive (P) and negative (N) inputs.

  • Initialize w randomly.
  • Iterate over all samples P ∪ N (P union N), picking a random x each time.
  • If x ∈ P we need w·x ≥ 0. If x ∈ N we need w·x ≤ 0 (strictly < 0 in the pseudo-code logic).
  • Only when these conditions are NOT met do we update the weights.
P ← inputs with label 1 N ← inputs with label 0 Initialize w randomly while !convergence: pick random x ∈ P ∪ N if x ∈ P and w·x < 0: w = w + x if x ∈ N and w·x ≥ 0: w = w − x // converges when ALL inputs are classified correctly
Worked example. x = [1, 2, 1] ∈ P, w = [0, −1, 0].
w·x = 0 − 2 + 0 = −2 < 0 → wrong!
Update: w = w + x = [1, 1, 1]. New w·x = 1 + 2 + 1 = 4 > 0 ✓.

Intuition: a misclassified positive means w points away from x, so add x to pull w toward it. A misclassified negative means w points too close to x, so subtract x to push w away.

6. Geometry view: angle between vectors
wᵀx = ‖w‖·‖x‖·cos α cos α = wᵀx / (‖w‖‖x‖) α = arccos( wᵀx / (‖w‖‖x‖) )

Since the magnitudes are always positive, cos α ∝ wᵀx: the sign of the dot product equals the sign of cos α.

  • wᵀx > 0 ⇒ cos α > 0 ⇒ α < 90° (x ∈ P ✓)
  • wᵀx < 0 ⇒ cos α < 0 ⇒ α > 90° (x ∈ N ✓)

So: any w that makes an angle < 90° with every positive vector and > 90° with every negative vector is a good solution.

Diagram: the classifier line is wᵀx = 0; w is perpendicular to the line; P points (p₁,p₂,p₃) lie on w's side, N points (n₁,n₂,n₃) on the other. The hyperplane is H = {x : dot(x,w) + b = 0}: dot(x,w)+b > 0 on the positive side, < 0 on the negative side.

7. Pocket Algorithm

The Pocket Algorithm is the "advanced version" of the perceptron. PLA only works for linearly separable data (and loops forever otherwise). Pocket is used when data is not linearly separable and you want to separate it with the minimal error. You can test it on your own generated data; it need not be separable.

Slide function: f(x) = 1 if w·x + b > 0, else 0; w = real-valued weight vector, b = bias, x = input feature vector.

  1. Initialize W_pocket to 0 or small random numbers; use it as the initial weight vector W₀ of PLA.
  2. For each training iteration:
    1. Run the PLA training step → updated Wt (t = current iteration).
    2. Evaluate Wt: compare its number of misclassifications on the entire sample set with that of W_pocket.
    3. If Wt is better, replace W_pocket with Wt.
  3. Return W_pocket when training terminates.
Analogy: you walk around (PLA wanders), and keep the best result you've found so far in your pocket. At the end you hand over the pocket, not wherever you happen to be standing.
8. MNIST dataset
  • 70,000 grayscale images of handwritten digits 0–9.
  • Each image is a 28×28 pixel square → 784 (28·28) features.
  • Every image is labelled with the digit it represents (0–9).
  • Each feature = one pixel's intensity, from 0 (white) to 255 (black).

An image is just a grid of numbers: the slide shows a "3" as a 28×28 matrix with 0s for background and values up to 253–255 on the stroke. Flatten the grid to a 784-long vector = the input x. (Perceptron is binary, so a typical use is "is it digit d or not?", mapping labels to 0/1.)

Smart Summary

Perceptron

  • Only linearly separable functions
  • Σwᵢxᵢ + b → activation → binary
  • x₀=1, w₀=−θ folds bias in
  • Labels 0/1 → Heaviside; −1/1 → sign

PLA

  • Random w; random x ∈ P∪N
  • x∈P & w·x<0 → w+x
  • x∈N & w·x≥0 → w−x
  • Update only on mistakes
  • Converges when all correct

Geometry

  • w·x = ‖w‖‖x‖cos α
  • P: α < 90° · N: α > 90°
  • w ⟂ hyperplane
  • H: w·x + b = 0

Pocket

  • PLA + keep best w
  • For non-separable data
  • Compare #misclassified on full set
  • Return W_pocket

MNIST

  • 70,000 images · 0–9
  • 28×28 = 784 features
  • Pixel 0 (white) → 255 (black)
  • Labelled
Mnemonics.
• "P-lus, N-egative-minus": P mistake → +x; N mistake → −x.
• "PLA = Plays Until All" correct; Pocket = Pockets the Best.
• Angle 90 rule: P "pleasant" (<90°), N "nasty" (>90°).
• 784 = 28 × 28: "28 squared, 784 fair."

Common mistakes & traps

  • Updating weights when the point is already correct. PLA updates only on mistakes.
  • Mixing up signs: P error → add, N error → subtract.
  • Using sign with 0/1 labels (or step with −1/1).
  • Forgetting x₀ = 1 in the x vector, or the bias weight w₀ in w.
  • Saying PLA works on any data. It needs linear separability to converge.
  • Thinking Pocket returns the last w. It returns the best one.
  • MNIST: 784 is the number of features per image, not the number of images (70,000).
  • Slide wording: "cosine of the slope" really means the angle between w and x.
