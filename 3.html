Linear Classification & Perceptron

Source note: the lecture was an auto-transcript of Egyptian Arabic mixed with English and had gaps. Everything below is reconstructed from its clear parts (this is the Perceptron Learning Algorithm, PLA lecture).
1. The big goal: classification with a line

We have points of two classes. We want a straight line that puts one class on the positive side (above) and the other on the negative side (below). A point on the wrong side is misclassified.

Analogy: a fence in a field separating sheep from goats. Misclassified = an animal on the wrong side.

2. Slope (انحدار / ميل) and the line equation

Slope = Δy / Δx = how much y changes per change in x (translations: ميل / انحدار; “regression” also literally means انحدار). Line: y = mx + b.

The lecturer drops b (the intercept) at first, so the line passes through the origin. Then two lines with the same slope are the same line; different slope means a different line, which means a different classification.

3. Points and lines as vectors

A point in space is described by its coordinates (x, y, z): its distances along each axis from the origin. A vector is a point plus a direction (and a magnitude = its length/“strength”), measured from the origin.

A line is represented by one vector w (the weights) that is always perpendicular to the line and points toward the positive side. Rotate the line and w rotates with it, staying perpendicular. This replaces writing the full line equation.

Analogy: w is a flag pole standing straight up from a wall; the flag points to the “positive” room.

4. Deciding the sign: the dot product

For a point x, look at the angle between w and x:

  • Acute (< 90°) → same side as w → positive, w·x > 0
  • Obtuse (> 90°) → opposite side → negative, w·x < 0
  • Exactly 90° → on the line → w·x = 0, neither class (ambiguous)

Dot product: multiply matching components, then add: w·x = w₁x₁ + w₂x₂ + … The result is a single number (scalar); only its sign matters: h(x) = sign(wᵀx).

Transpose: to multiply two column vectors as matrices we write wᵀx (row × column). Same operation, proper notation.

Contrast: the Cartesian product pairs every element with every other; the dot product multiplies matching elements and sums them.

5. The bias (intercept) trick

In y = mx + b, treat b as a weight on an extra input that is always 1 (the intercept’s coefficient is always 1). So x = (1, x₁, …) and w = (b, m, …). Now the whole thing is just wᵀx.

6. Fixing a mistake: the update rule (the heart of PLA)

Take a misclassified point x with true label y ∈ {+1, −1}. Move w using vector arithmetic; the new line is perpendicular to the new w.

SituationAngle w–xUpdateEffect
Should be positive, but is negativeObtusew ← w + xNew w tilts toward x, angle shrinks, x pulled to the positive side
Should be negative, but is positiveAcutew ← w − xNew w tilts away from x, angle grows past 90°

Compactly: w_new = w_old + y·x (y = +1 adds, y = −1 subtracts). Adding gives a vector “in between” the two; subtracting gives one pushed “outside”.

Caution: fixing one point can break others (the line moves!). So we loop over the data repeatedly until no point is misclassified.

7. Hypothesis vs target function

The target function f is the true, unknown rule. If we knew it we would not need learning. We instead choose a hypothesis h (a guess, here a line defined by w) and use the data to tune it so h ≈ f. Sometimes the first guess is a misclassified point; that is normal and is exactly what the data corrects.

Key idea: Can the data teach us the rule? Yes. The computer is fast, but a human decides how it thinks (the model and the algorithm).

8. When a line is not enough: polynomial features

If classes are arranged so no straight line separates them, use a curve, e.g. ax² + bx + c = 0. Add x² as a new feature, and the model is still linear in its features, so the same PLA works. Polynomial degree = the largest exponent (x³ → degree 3). More degree = more flexible curve (the lecturer: keep adding terms until the curve fits the data).

Which matters more, x or y? Both; but we always look at y (the outcome): did it go up or down?

  • Goal: separate two classes with a line → positive / negative sides.
  • Slope = Δy/Δx (ميل/انحدار). Same slope & through origin ⇒ same line.
  • Vector = coordinates + direction (+ magnitude).
  • w ⟂ line, pointing to the positive side.
  • Sign test: sign(wᵀx); acute ⇒ +, obtuse ⇒ −, 90° ⇒ on the line.
  • Dot product: multiply matching entries, then sum → scalar.
  • Bias: extra input x₀ = 1.
  • Update: missed positive → w + x; missed negative → w − x.
  • Repeat until zero errors (works if data is linearly separable).
  • Target f unknown vs hypothesis h (our guess).
  • Non-separable? add polynomial terms (x²…); degree = max exponent.

Common mistakes & traps

Confusing the line with w: w is perpendicular to the line, not along it.
Mixing up the signs of the update (add for a missed positive).
Thinking one update fixes everything: it can break other points; loop until no errors.
Calling the dot product a vector: it is a scalar. Mixing it up with the Cartesian product.
Forgetting the bias input of 1; forgetting a point with w·x = 0 is neither class.
Thinking polynomial regression is “non-linear learning”: it is linear in the transformed features.

Night-before cheat sheet

  1. Line ⇄ vector w (⟂ line, points to positive side).
  2. Classify: h(x) = sign(wᵀx). Acute >0, obtuse <0, 90° = 0.
  3. Dot product = Σ wᵢxᵢ (scalar).
  4. Bias: x₀ = 1.
  5. Missed positive: w ← w + x. Missed negative: w ← w − x. Same as w ← w + y·x.
  6. Loop until no mistakes; one fix may break another.
  7. f = unknown truth, h = hypothesis.
  8. No line works → add x², x³… (degree = highest exponent), still linear in features.
  9. Slope = Δy/Δx = ميل = انحدار.
